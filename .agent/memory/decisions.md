# 架构决策记录（ADR）

本文件用于记录已采纳的重要技术与架构决策。每条记录应包含：背景、决策、备选方案、后果与验证方式。

## ADR-0001：采用仓库内可追溯的 Codex 上下文结构

- 状态：Accepted
- 日期：2026-10-02

### 背景

需要一个可长期演进的协作骨架，使规则、提示词、模板、任务与决策可版本化、可检索、可复用。

### 决策

在仓库内建立 `.codex/` 目录，按 rules/prompts/templates/snippets/tasks/memory/scripts 分层管理。

### 备选方案

- 仅依赖外部知识库或对话历史：难以版本化与审计
- 仅维护一份大而全的说明文档：演进成本高，复用性差

### 后果

- 正面：协作一致性提升，关键知识可追溯
- 负面：需要持续维护文档与模板

### 验证方式

- 新成员可在 10 分钟内理解规则与工作流
- 关键决策在仓库内可检索并可回溯到变更记录

## ADR-0002：增加专用 “Hunter” 研究与归档 Agent

- 状态：Accepted
- 日期：2026-10-08

### 背景

仓库的核心任务包括搜索论文与项目、按类别归档并撰写说明文档，因此需要一个与该工作强绑定的 Agent 角色，而不是仅依赖通用对话。

### 决策

在 `.github/agents/` 中定义 `hunter` Agent，并在 `.agent/agents/hunter/` 中维护其工作说明和目录约定，用于统一研究、筛选、归档与文档输出流程。

### 备选方案

- 仅使用通用对话：容易导致产出不统一、目录不清晰
- 不建立 Agent 文档：无法对角色职责和交付标准形成共识

### 后果

- 正面：研究与整理任务可标准化、可复用、可审计
- 负面：需要持续维护角色说明与目录约定

### 验证方式

- 在仓库中可直接定位到 Agent 定义文件和角色说明
- 新任务可按统一步骤完成定位、分类、归档与说明文档输出
